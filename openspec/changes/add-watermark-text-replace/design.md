# Design

## Context

GUI 今天只有擦除路径：`ImageCanvas` 收集 `Region`，`ProcessingPipeline` 把选区并成 mask，缩略图上用 LaMa 出预览，导出时把 mask 映射回原图再 inpaint，最后走 `export_profile`。EasyOCR 只在 CLI 角落检测里使用（`detector.py` 的 `WatermarkDetector`）。工程已依赖 Pillow、PySide6、EasyOCR、LaMa，没有字体文件。见 proposal.md 的范围：只做离线黑体/宋体重绘。

## Goals / Non-Goals

**Goals:**

- 替换模式与擦除模式的数据和图不混用
- 一块矩形对应一段文案；预览在缩略图，导出在原图重做
- 样式只估计位置、字号、颜色；字体二选一
- 不增加 pip 包，不增加模型文件

**Non-Goals:**

- CLI 文案替换
- 花字、渐变、描边、投影、弯曲文字
- 从像素反推真实字体文件
- 椭圆、多边形、套索作为文案框

## Decisions

### 1. 模式与数据分开存

`ImageTask` 增加工作模式（擦除 / 替换）和 `text_boxes` 列表，与现有 `regions` 并列。文案框字段：缩略图坐标矩形、目标文案、字体（黑体或宋体）、识别是否成功。

擦除预览继续只读 `regions`。替换预览只读非空 `text_boxes`。切换模式、改框、改文案、改字体都走与 `invalidate_preview` 相同的作废规则。

备选：给 `Region` 加文字字段。会让擦除并集 mask 和文案语义缠在一起，否决。

### 2. 替换流水线

新模块负责单框处理，由 `ProcessingPipeline` 调用，不改 CLI。

缩略预览与原图导出共用同一算法，坐标按 `ImageTask.scale` 映射（与现有 mask 放大同一比例）：

1. 在矩形内跑 EasyOCR（复用 `WatermarkDetector` 已加载的 Reader，避免第二份模型）
2. 取框内文字外接矩形；没有结果则用整个用户矩形
3. 在该外接矩形内做局部二值，得到字形 mask（只盖笔画，不盖整块底）
4. LaMa inpaint 该 mask
5. 估计样式：位置为文字外接矩形中心；颜色为字形像素的中位色；字号从原文字高度起，用 Pillow 测量，放不下宽度就递减，直到整句落在矩形内
6. 用所选字体画单行文字（抗锯齿），贴回 inpaint 结果

一块框一行。用户要两行就画两块框。多块按列表顺序依次处理。

识别时机：矩形提交时在后台识别并回填，不在选图时识别。用户随后把回填原文改成目标句。生成预览时不再二次识别，以免改过的句子被覆盖。

### 3. 字体文件

随仓库放置两份 OFL 字体子集，界面名称映射为「黑体」「宋体」（思源黑体 / 思源宋体或 Noto Sans SC / Noto Serif SC 的常用汉字子集）。运行时只从应用目录加载，不查找系统字体，这样无中文字体的 Linux 安装包行为一致。

打包：`watermark_remover_gui.spec` 的 `datas` 增加 `fonts/`，与现有 `models` 并列。不把字体打进模型下载脚本。

子集会让安装包增加字体文件体积（预期每份数 MB 到十余 MB），不增加 LaMa / EasyOCR 模型。这是「离线且不用生成模型」的代价，也是相对数 GB 模型而言体积基本不变的含义。

备选：用系统「微软雅黑 / 宋体」。Windows 上省体积，Linux 离线包经常没有这些字体，否决。

### 4. 界面

形状行增加模式切换：「擦除」「替换文案」。替换模式下形状按钮禁用，画布只出矩形。矩形下方增加当前框的文案输入和字体下拉；多框时选中某一框再编辑。生成预览、确认、导出按钮沿用现有槽位，按当前模式分支。

替换预览走现有 `worker` 后台线程，避免 OCR 与 LaMa 卡住界面。

### 5. 导出

替换确认图导出时：加载原图 → 按比例放大各文案框 → 跑决策 2 的算法 → `apply_export_profile`。不放大缩略预览。擦除导出路径不改。

## Risks / Trade-offs

- [字形二值把背景算进 mask，LaMa 抹出一块补丁] → mask 限制在 OCR 外接矩形内，并要求笔画与周围有对比；失败时预览仍可让用户收小矩形重试
- [描边字取色取到描边而不是填充] → 接受。规格只要求颜色接近，不要求分层样式
- [新句子很长导致字号过小] → 按规格缩小到放进矩形；README 说明应拆成多框或缩短文案
- [EasyOCR 在缩略图上漏字] → 框保留，文案留空，提示手填；字号退化为按用户矩形高度估计
- [字体子集缺字] → 子集覆盖常用汉字与数字、基本拉丁；缺字在预览中表现为方框，README 的 FAQ 写明

## Migration Plan

纯新增 GUI 能力。旧的擦除选区数据只存在于进程内，无持久化迁移。回退时去掉替换模式入口与字体 datas 即可，擦除路径独立。
