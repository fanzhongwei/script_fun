## MODIFIED Requirements

### Requirement: 回填原页面表格

活动配置区下方 SHALL 提供唯一「回填」按钮。点击后，系统 SHALL 将所有已计算出有效拼单价与单买价的 SKU 行写入扫描时记录的原始表格对应输入框，行列 MUST 与款式行一一对应。不支持逐行单独回填。

系统 MUST 采用分批异步回填，批次之间 MUST 让出主线程，避免大量 SKU 时页面长时间无响应。回填进行中 MUST 展示进度提示（已处理行数 / 待回填有效行总数），并 MUST 禁用「回填」按钮直至本次回填结束。

回填结束后 MUST 提示成功、跳过、失败数量；同一行 MUST NOT 同时计入成功与失败。无有效价格的行 MUST 计入跳过且不写入。写入失败或校验失败的行 MUST 仅计入失败。

#### Scenario: 全部回填成功

- **WHEN** 用户点击「回填」且至少一行拼单价、单买价已有效
- **THEN** 原页面表格中所有对应行的拼单价、单买价输入框被更新为各自计算结果，并提示成功数量

#### Scenario: 部分行无效时跳过

- **WHEN** 用户点击「回填」但部分行成本为空导致无有效价格
- **THEN** 系统跳过无效行，回填有效行，并提示成功与跳过数量

#### Scenario: 分批回填与进度提示

- **WHEN** 用户点击「回填」且有效行数量较多
- **THEN** 系统分批写入并展示「回填中 m/n」类进度提示，完成后展示汇总结果；回填期间「回填」按钮不可再次触发

#### Scenario: 结果统计互斥

- **WHEN** 某一行成功写入拼单价与单买价
- **THEN** 该行计入成功，不得同时计入失败

#### Scenario: React 受控输入框回填

- **WHEN** 原页面输入框为框架受控组件
- **THEN** 系统通过原生 value 赋值并派发 `input`/`change` 事件，确保页面状态同步
