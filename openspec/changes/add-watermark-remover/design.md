## Context

仓库已有 `python/turnstile_verify`（OpenCV 模板匹配）与 Tampermonkey `image_exporter` / `pdd_product_importer` 铺货链路。AI 生成商品图常带角落半透明水印（如「豆包AI生成」），需在本地预处理后上架。约束见 proposal.md：本机 CPU、小批量（≤20 张）、优先覆盖 AI 平台角落文字水印。

## Goals / Non-Goals

**Goals:**

- 新增 `python/watermark_remover/` CLI 脚本，单张与目录批量处理
- 自动检测：四角 ROI + OCR + `patterns.yaml` 关键词匹配
- 自动修复：LaMa inpainting，复杂纹理背景效果优于 OpenCV Telea/NS
- 预览模式：输出 mask 叠加图，用户确认后再修复
- 兜底：`--region br|bl|tr|tl` 或比例坐标手动指定修复区域
- README 含环境依赖、参数说明、配置说明、FAQ

**Non-Goals:**

- GPU 加速、分布式批处理
- 平铺「sample」斜纹、频域隐形、全图语义水印
- 集成进 Tampermonkey 或浏览器内实时处理
- 专用 watermark detection 深度学习模型（SAM/U-Net）
- 修改现有 `tampermonkey/`、`linux/` 脚本

## Decisions

### 1. 目录结构与模块划分

- **决策**：`python/watermark_remover/` 单目录，内含：
  - `watermark_remover.py` — CLI 入口
  - `detector.py` — ROI 裁剪、OCR、mask 生成
  - `inpainter.py` — LaMa 修复封装
  - `patterns.yaml` — AI 水印关键词与 ROI 参数
  - `requirements.txt`、`README.md`
- **理由**：与仓库「每脚本一目录」惯例一致；模块少、职责清晰，十几张规模无需过度抽象
- **备选**：单文件脚本 — 可维护性差，放弃

### 2. 水印检测策略

- **决策**：分层检测，按优先级：
  1. 若指定 `--region`，跳过 OCR，直接按角落或比例坐标生成 mask
  2. 否则按 `patterns.yaml` 的 `corner_priority`（默认 `br, bl, tr, tl`）依次裁剪 ROI
  3. 对每个 ROI 运行 EasyOCR（中文+英文），匹配 `keywords` 列表（子串命中即可）
  4. 命中后取 OCR bbox，外扩 `padding_px`（默认 5px）生成二值 mask
- **理由**：AI 水印 90%+ 在角落且文案固定，OCR + 关键词足够；无需 ML 检测模型
- **备选**：PaddleOCR — 中文略优但依赖更重；MVP 先用 EasyOCR，后续可切换
- **备选**：OpenCV 半透明 overlay 启发式 — 对变体文案鲁棒性不足，作 OCR 补充而非主路径

### 3. 修复引擎

- **决策**：使用 `simple-lama-inpainting` 包加载 LaMa TorchScript 模型（CPU 推理，`map_location=cpu`）
- **理由**：比 lama-cleaner 依赖更轻、安装更简单；用户样例复杂纹理下效果优于 OpenCV
- **备选**：lama-cleaner — tokenizers 需 Rust 编译，本机安装失败
- **备选**：OpenCV Telea/NS — 仅作 `--engine opencv` 可选降级，非默认

### 4. CLI 接口

- **决策**：

```bash
# 单张自动
python3-dev watermark_remover.py -i input.png -o output.png

# 预览 mask（不修复）
python3-dev watermark_remover.py -i input.png --preview -o ./preview/

# 批量目录
python3-dev watermark_remover.py -i ./ai_images/ -o ./clean/

# 手动指定右下角落
python3-dev watermark_remover.py -i input.png --region br

# 手动比例坐标 (x1,y1,x2,y2 相对 0~1)
python3-dev watermark_remover.py -i input.png --region 0.75,0.85,1.0,1.0
```

- **输出**：修复图写入 `-o`；`--preview` 额外输出 `{stem}.mask.png`（mask 叠加）与 `{stem}.mask.bin.png`（纯 mask）
- **批量**：遍历目录内 `.png/.jpg/.jpeg/.webp`，跳过已存在输出文件（除非 `--force`），末尾打印成功/失败/跳过统计

### 5. patterns.yaml 配置

- **决策**：

```yaml
roi:
  width_ratio: 0.25    # 角落 ROI 宽占整图比例
  height_ratio: 0.15   # 角落 ROI 高占整图比例
  padding_px: 5        # OCR bbox 外扩像素

corner_priority: [br, bl, tr, tl]

keywords:
  - 豆包AI生成
  - 豆包
  - 即梦
  - 即梦AI
  - 通义万相
  - 文心一格
  - AI生成
  - AI作图
  - Generated by
```

- **理由**：用户可随新平台扩展关键词，无需改代码
- **加载**：默认读脚本同目录 `patterns.yaml`；`--config` 可指定自定义路径

### 6. 预览与确认流程

- **决策**：`--preview` 只检测 + 输出 mask 预览，不写修复图；不加交互式 TUI（小批量用户肉眼检查 preview 目录即可）
- **理由**：十几张规模，文件预览比终端交互更简单可靠
- **备选**：`--yes` 跳过预览直接修复 — 支持，供用户确认策略稳定后使用

### 7. 依赖与运行环境

- **决策**：`requirements.txt` 固定主要版本；Python 3.9+；命令使用 `python3-dev` / `pip3-dev`
- **首次运行**：LaMa 模型自动下载至用户缓存目录（约 200MB），README 说明
- **torch**：安装 CPU 版（`--index-url` 或 requirements 注释指引）

## Risks / Trade-offs

- **[Risk] OCR 漏检新平台文案** → `patterns.yaml` 可扩展；`--region br` 手动兜底
- **[Risk] OCR 误检正文标题** → 仅扫描角落 ROI + 关键词白名单；标题通常在画面中上部，风险低
- **[Risk] LaMa CPU 推理慢** → 十几张可接受；README 给出耗时预期
- **[Risk] 复杂背景修复留痕** → 预览模式让用户确认；必要时手动缩小 `--region` 仅覆盖文字
- **[Risk] 首次安装依赖较重（torch + easyocr）** → README 分步安装指引；与 turnstile_verify 一样一次性配置
- **[Trade-off] 不做交互确认** → 降低实现复杂度；用户通过 `--preview` 两步操作弥补

## Migration Plan

- 纯新增目录，无迁移
- 部署：`pip3-dev install -r requirements.txt`，首次运行触发模型下载
- 回滚：删除 `python/watermark_remover/` 目录即可，不影响其他脚本
