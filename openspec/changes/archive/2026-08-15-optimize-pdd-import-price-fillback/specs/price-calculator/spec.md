## MODIFIED Requirements

### Requirement: 默认值与可编辑参数

弹窗初始化时，每行 SHALL 使用下列默认值（用户可修改）：

| 字段 | 默认值 |
|------|--------|
| 采购成本 | 空（待用户填写或粘贴） |
| 运费 | 0 |
| 退货率 | 20（%） |
| 目标利润率 | 30（%） |
| 平台扣点 | 0.6（%） |

实际成本、实际利润率、实际利润、净保本投产比、微付费投产比、最佳投产比、实际拼单价、拼单价、单买价 SHALL 由系统根据当前计算结果自动更新，不可手动编辑。

#### Scenario: 初始化默认值

- **WHEN** 弹窗首次打开并完成 SKU 扫描
- **THEN** 每行中间列可编辑参数填充为上述默认值，其中目标利润率为 30%

### Requirement: 活动配置与叠加规则

弹窗右侧固定列表头 SHALL 提供**全局**活动配置区（对所有 SKU 行统一生效），包含下列控件：

1. 立减优惠券（元）——默认 **5**，且 MUST ≥ 0
2. 限时限量购：活动类型下拉（打折 / 立减）+ 数值输入（打折为百分比 0～100；立减为元 ≥ 0）——限时限量购数值默认 0

活动区下方 SHALL 放置唯一「回填」按钮（见回填需求）。

叠加规则：

- 拼单价 = 实际拼单价 + 活动优惠价格
- 活动优惠价格 = 立减优惠券金额 + 限时限量购加价部分（立减为 +v；打折为反推挂牌价产生的加价）
- 无活动或金额均为 0 时，拼单价 = 实际拼单价
- 全局活动配置变更时，所有 SKU 行 SHALL 同步重算

#### Scenario: 立减优惠券抬高挂牌价

- **WHEN** 用户设置立减优惠券为 5 元且无其他活动
- **THEN** 所有 SKU 行的拼单价 = 实际拼单价 + 5，实际拼单价与利润指标不变

#### Scenario: 全局活动同步重算

- **WHEN** 用户修改全局活动金额或限时限量购类型/数值
- **THEN** 所有 SKU 行的拼单价、单买价与衍生指标立即重算

#### Scenario: 限时限量购叠加

- **WHEN** 用户在已设置立减优惠券的基础上配置限时限量购
- **THEN** 系统在（实际拼单价 + 立减优惠券）结果上继续应用限时限量购计算最终拼单价与单买价

#### Scenario: 活动默认值为零

- **WHEN** 弹窗初始化完成且用户未导入 Markdown
- **THEN** 立减优惠券默认 5 元，限时限量购数值为 0

### Requirement: 回填原页面表格

活动配置区下方 SHALL 提供唯一「回填」按钮。点击后，系统 SHALL 将所有已计算出有效拼单价与单买价的 SKU 行写入原页面，行列 MUST 与款式行一一对应。不支持逐行单独回填。

优先通过 React `sku.tableList` 批量写入 `multi_price`（拼单价，分）与 `price`（单买价，分），并按款式 `spec` 匹配；匹配失败时按行序兜底。SKU 价格写入成功后，系统 SHALL 将页面「商品参考价」（`#market_price` 区域内数值输入框）更新为 **所有已回填 SKU 单买价的最大值 + 2**（保留两位小数；无有效单买价时跳过此步）。写入完成后 SHALL 自动点击页脚「保存草稿」提交。若无法访问 `tableList`，SHALL 回退为逐行对输入框派发 `input` 事件，并在事件兜底路径成功写入 SKU 价格后同样尝试更新商品参考价。

回填进行中 MUST 展示进度或阶段提示，并 MUST 禁用「回填」按钮直至本次回填结束。回填结束后 MUST 提示成功、跳过、失败数量；同一行 MUST NOT 同时计入成功与失败。

#### Scenario: 全部回填成功

- **WHEN** 用户点击「回填」且至少一行拼单价、单买价已有效
- **THEN** 原页面 SKU 价格被更新为各自计算结果，并提示成功数量

#### Scenario: 回填后更新商品参考价

- **WHEN** 用户点击「回填」且有效 SKU 行的单买价分别为 68.5、74.1、71.0
- **THEN** 系统将商品参考价输入框设为 76.1（74.1 + 2）

#### Scenario: 无有效单买价时跳过参考价

- **WHEN** 用户点击「回填」但所有行均无有效单买价
- **THEN** 系统不修改商品参考价输入框

#### Scenario: 部分行无效时跳过

- **WHEN** 用户点击「回填」但部分行成本为空导致无有效价格
- **THEN** 系统跳过无效行，回填有效行，商品参考价仅基于有效行的单买价最大值 + 2，并提示成功与跳过数量

#### Scenario: 分批回填与进度提示

- **WHEN** 用户点击「回填」且有效行数量较多，且走事件兜底路径
- **THEN** 系统分批写入并展示进度提示，完成后展示汇总结果；回填期间「回填」按钮不可再次触发

#### Scenario: 结果统计互斥

- **WHEN** 某一行成功写入拼单价与单买价
- **THEN** 该行计入成功，不得同时计入失败

#### Scenario: tableList 回填并保存草稿

- **WHEN** 用户点击「回填」且页面存在 `sku.tableList`
- **THEN** 系统批量更新 tableList、更新商品参考价后自动点击「保存草稿」
