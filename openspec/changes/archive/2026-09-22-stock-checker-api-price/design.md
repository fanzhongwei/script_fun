## Context

库存检查脚本在爱用分销商品列表上切店、翻页，再逐件点进规格匹配页读 DOM。货源卡片上已有价格文案（形如 `价格：¥9.9`）。曾计划改走爱用接口加速，但轻应用文档里没有可被用户脚本复用的请求签名，该方案已放弃。店铺列表与商品列表仍由页面控制。见 `proposal.md`。

## Goals / Non-Goals

**Goals:**

- 店铺切换、当前筛选、商品列表翻页、规格匹配页采集保持现有页面流程。
- 在规格页读取货源卡片价格，按店铺存在油猴本地，检查时对比涨跌，并写入单独的价格 Sheet。
- 库存判定树和两个库存 Sheet 的列保持不变。

**Non-Goals:**

- 不调用爱用接口，不用 `getItemList` 代替页面列表，不改筛选。
- 不把价格存到飞牛或其它远端。
- 不在脚本或 Excel 中保存令牌、签名、账号密码。
- 不处理多货源；仍只取当前一条关联。

## Decisions

### 1. 只走规格匹配页

每一件商品点击「规格匹配」，等待规格页，选「全部规格」，取消「仅上架」，读取当前表格全部 SKU，再点面包屑返回商品列表。相邻商品之间停顿约 1.5 秒。不发爱用接口，不加 `unsafeWindow`。

**备选**：复用页面请求走 `getLowBabyRelation`、`getItemInfos`、`getItemSkuRelation`、`getSkuOnsale`。轻应用里找不到已登录的请求方法，故放弃。

### 2. 货源价从卡片读取

货源价选择器为 `.product-specs-card-info-price .sku-info-price`。不要用行内任意 `.sku-info-price`，货源库存格也使用了这个 class。店铺售价（`.sku-info-content .sku-info-price`）不采集。只在已关联时读取。对比与存档用分（四舍五入到分）。

### 3. 失败与重试

打开规格匹配、等待表格、读取规格或返回列表任一失败，整段立即重试，最多 5 次（含首次）。5 次仍失败则库存明细记 `检查失败`，不改该商品已存价格，然后继续下一件商品。

### 4. 货源价存档

存档键：`sc-source-price:v1:<店铺名>`。值为映射，SKU 键为 `店铺商品ID + 店铺SKU名`，值含价格（分）、货源 SKU 名、记录时间。先对比再覆盖。本次无货源价则保留旧值，涨跌为 `无货源价`。某件商品成功后立即写入该店存档，避免跑到一半关闭页面丢掉已完成的商品。检查失败的商品整件跳过写入。

涨跌顺序：无本次价 → `无货源价`；无上次价 → `首次`；两边货源 SKU 名都非空且不同 → `换绑`；否则按分比较得到涨价、降价或持平。涨跌额为本次减上次（元，两位小数）；`换绑` 也写差额。

脚本头只增加 `@grant GM_getValue`、`@grant GM_setValue`。

### 5. Excel

仍按店铺各一份文件。库存两个 Sheet 的列、筛选、红/黄行背景不变。新增：

- 「待处理价格」：涨跌为涨价、降价、换绑
- 「价格检查明细」：成功核对的全部 SKU

价格列：店铺商品ID、店铺商品名、店铺SKU名、货源SKU名、上次货源价、本次货源价、涨跌、涨跌额、货源名称、货源供应商。合并列仍是店铺商品ID、店铺商品名、货源名称、货源供应商。涨跌单元格：涨价红字、降价绿字、换绑橙字，不给整行涂库存色。总结增加涨价、降价、换绑计数；若有「首次」，提示基准价已记下。

## Risks / Trade-offs

- [全店仍逐件打开规格页] → 速度与改接口之前相同；接口方案已确认在当前轻应用里不可用。
- [只存最新价，换浏览器没有上次价] → 该次全部为「首次」，不进待处理价格。
- [货源卡片价格文案改版] → 读不到价格时记 `无货源价` 并保留旧存档，库存判定仍按原规则完成。

## Migration Plan

- 更新油猴脚本后，Tampermonkey 会提示新增存储权限。确认后下次检查开始积累基准价。
- 回滚：装回旧版本脚本。本地存档留在油猴里，旧版本不读取，不影响库存表。
