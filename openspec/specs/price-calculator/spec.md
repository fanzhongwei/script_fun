# price-calculator Specification

## Purpose

拼多多商家后台 SKU 拼单价/单买价计算器：扫描规格表格、正向加价定价、活动叠加、投产比指标、Markdown 导入导出与一键回填。

## Requirements

### Requirement: 可拖动悬浮入口

脚本 SHALL 在匹配页面提供固定悬浮按钮，文案为「价格计算」，样式与交互参照 `image_exporter` 的 FAB（可拖动、位置持久化）。点击该按钮 SHALL 打开价格计算器弹窗；弹窗关闭后悬浮按钮仍保留。

#### Scenario: 打开计算器弹窗

- **WHEN** 用户点击「价格计算」悬浮按钮
- **THEN** 系统展示价格计算器弹窗，并开始扫描当前页面 SKU 表格

#### Scenario: 关闭计算器弹窗

- **WHEN** 用户在弹窗中选择关闭
- **THEN** 弹窗消失，悬浮按钮仍保留在页面上

### Requirement: 扫描页面 SKU 表格

脚本 SHALL 在当前页面查找包含至少一列规格属性（如款式、颜色、尺寸、型号等）与「拼单价」列头的 SKU 表格，提取每行数据用于计算与回填：

- **款式**：SHALL 拼接该行所有规格列（表头语义匹配规格属性的全部列）的文本，以 ` / ` 分隔；当某规格列因 rowspan 合并导致当前行 cell 为空时，SHALL 沿用上一条非空值（carry-forward）。当 body 行 td 数少于表头时，SHALL 按 `offset = 表头列数 - 当前行 td 数` 补偿列索引后再取对应 cell
- **拼单价 / 单买价输入框**：优先按行内 DOM 顺序定位——第一个 `.sku-beast-price-input-container input` 为拼单价，第二个为单买价；若行内不足两个 price input，则 fallback 到 offset 补偿后的表头列索引
- **采购成本初始值**：若拼单价输入框当前值 > 0，SHALL 作为该行采购成本的初始值

#### Scenario: 成功扫描 SKU 行

- **WHEN** 页面存在符合条件的 SKU 表格且至少有一行数据
- **THEN** 弹窗中生成与页面行数对应的计算列表，每行包含拼接后的款式文本

#### Scenario: 未找到 SKU 表格

- **WHEN** 页面不存在符合条件的 SKU 表格
- **THEN** 弹窗展示空状态提示，并说明未找到可识别的规格表格

#### Scenario: 多规格 rowspan 表格正确初始化

- **WHEN** SKU 表格包含多个规格列（如「型号」与「尺寸」），且第一个规格列使用 rowspan 合并
- **THEN** 每行款式文本为各规格列值的 ` / ` 拼接（如「经典款 / 大号」），而非仅最后一个规格列
- **AND** 每行采购成本初始值取自该行拼单价输入框的当前值（> 0 时填入）

#### Scenario: 单规格表格行为不变

- **WHEN** SKU 表格仅有一列规格属性且无 rowspan 错位
- **THEN** 款式即为该规格列文本，采购成本取自拼单价输入框当前值

### Requirement: 弹窗尺寸与列布局

价格计算器弹窗 SHALL 宽、高均为浏览器视口的 80%（80vw × 80vh）。弹窗头部 SHALL 在「刷新」按钮之前提供【导出】【导入】两个主色按钮。表格 SHALL 采用左侧一列固定、中间区域可横向滚动、右侧固定的布局：

- 固定左列：款式（固定列宽，内容支持换行）
- 可滚动中间列（按顺序）：采购成本（元）、运费（元）、退货率（%）、平台扣点（%）、目标利润率（%）、实际成本（元）、实际利润率（%）、实际利润（元）、净保本投产比、微付费投产比、最佳投产比
- 固定右列：表头第一行合并单元格为全局活动配置区及「回填」按钮；表头第二行为「实际拼单价（元）」「拼单价（元）」「单买价（元）」；数据行展示各自行计算结果

#### Scenario: 弹窗尺寸

- **WHEN** 用户打开价格计算器弹窗
- **THEN** 弹窗面板宽高均为视口的 80%

#### Scenario: 中间列横向滚动

- **WHEN** 中间列总宽度超出可视区域
- **THEN** 用户可在中间区域横向滚动查看全部列，左右固定列保持可见

#### Scenario: 款式列换行显示

- **WHEN** 款式文本超出固定列宽
- **THEN** 文本在单元格内换行显示，不撑开列宽

### Requirement: 百分比字段输入范围

所有名称含「率」或「扣点」的可编辑字段（目标利润率、退货率、平台扣点）SHALL 以百分比形式展示与输入，取值范围 0～100（含边界）。实际利润率列为只读展示，同样以百分比形式显示。

#### Scenario: 百分比输入校验

- **WHEN** 用户在「率」类输入框中输入超出 0～100 的值
- **THEN** 系统拒绝该输入或将其钳制到合法范围内，并仍保持可计算状态

#### Scenario: 内部换算

- **WHEN** 系统执行价格计算
- **THEN** 将用户输入的百分比除以 100 后参与公式运算

### Requirement: 默认值与可编辑参数

弹窗初始化时，每行 SHALL 使用下列默认值（用户可修改）：

| 字段 | 默认值 |
|------|--------|
| 采购成本 | 空（待用户填写或粘贴） |
| 运费 | 0 |
| 退货率 | 20（%） |
| 目标利润率 | 20（%） |
| 平台扣点 | 0.6（%） |

实际成本、实际利润率、实际利润、净保本投产比、微付费投产比、最佳投产比、实际拼单价、拼单价、单买价 SHALL 由系统根据当前计算结果自动更新，不可手动编辑。

#### Scenario: 初始化默认值

- **WHEN** 弹窗首次打开并完成 SKU 扫描
- **THEN** 每行中间列可编辑参数填充为上述默认值，活动金额均为 0

### Requirement: 活动配置与叠加规则

弹窗右侧固定列表头 SHALL 提供**全局**活动配置区（对所有 SKU 行统一生效），包含下列控件，金额/数值输入默认 0、且 MUST ≥ 0：

1. 立减优惠券（元）
2. 限时限量购：活动类型下拉（打折 / 立减）+ 数值输入（打折为百分比 0～100；立减为元 ≥ 0）

活动区下方 SHALL 放置唯一「回填」按钮（见回填需求）。

叠加规则：

- 拼单价 = 实际拼单价 + 活动优惠价格
- 活动优惠价格 = 立减优惠券金额 + 限时限量购加价部分（立减为 +v；打折为反推挂牌价产生的加价）
- 无活动或金额均为 0 时，拼单价 = 实际拼单价
- 全局活动配置变更时，所有 SKU 行 SHALL 同步重算

#### Scenario: 立减优惠券抬高挂牌价

- **WHEN** 用户设置立减优惠券为 5 元且无其他活动
- **THEN** 所有 SKU 行的拼单价 = 实际拼单价 + 5，实际拼单价与利润指标不变

#### Scenario: 全局活动同步重算

- **WHEN** 用户修改全局活动金额或限时限量购类型/数值
- **THEN** 所有 SKU 行的拼单价、单买价与衍生指标立即重算

#### Scenario: 限时限量购叠加

- **WHEN** 用户在已设置立减优惠券的基础上配置限时限量购
- **THEN** 系统在（实际拼单价 + 立减优惠券）结果上继续应用限时限量购计算最终拼单价与单买价

#### Scenario: 活动默认值为零

- **WHEN** 弹窗初始化完成
- **THEN** 立减优惠券与限时限量购数值均为 0，拼单价等于实际拼单价

### Requirement: 正向加价定价与扩展指标

系统 SHALL 按下列公式计算（`目标利润率`、`退货率`、`平台扣点` 为已换算的小数；`C`=采购成本，`E`=运费）：

- 实际成本 = C + E
- 实际拼单价 = ROUND(实际成本 × (1 + 目标利润率), 2)
- 实际利润 = ROUND(实际拼单价 × (1 - 平台扣点) - C - E, 2)（不含退货率调整）
- 实际利润率 = ROUND(实际利润 / 实际成本 × 100, 2)（%; 实际成本 ≤ 0 时显示「—」）
- 净保本投产比 = ROUND((实际拼单价 / 实际利润) / (1 - 退货率), 2)（实际利润 ≤ 0 时显示「—」）
- 微付费投产比 = ROUND(净保本投产比 / 2 + 0.5, 2)
- 最佳投产比：当实际利润率 > 50% 时，`ROUND(净保本投产比 × 1.4, 2)`；当实际利润率 ≤ 50% 时，`ROUND(净保本投产比 × 2, 2)`
- 拼单价 = ROUND(实际拼单价 + 活动优惠价格, 2)
- 单买价 = ROUND(实际拼单价 × 1.1 + 立减优惠券金额 + 限时加价 + 随机偏移, 2)，其中随机偏移为每行 3～5 的固定随机小数（弹窗打开时生成）

#### Scenario: 无活动时的计算

- **WHEN** 用户填写采购成本 5.94、运费 0、目标利润率 20%、退货率 20%、平台扣点 0.6%，且无活动
- **THEN** 实际拼单价为 7.13，拼单价为 7.13，实际利润为 1.15，净保本投产比为 7.75

#### Scenario: 平台扣点降低实际利润

- **WHEN** 用户将平台扣点从 0% 改为 0.6%，其他参数不变
- **THEN** 实际拼单价不变，实际利润低于无扣点情形

#### Scenario: 实际利润非正时不展示投产比

- **WHEN** 某行参数导致实际利润 ≤ 0
- **THEN** 净保本投产比、微付费投产比、最佳投产比均显示「—」

#### Scenario: 高利率最佳投产比

- **WHEN** 某行实际利润率大于 50%
- **THEN** 最佳投产比 = ROUND(净保本投产比 × 1.4, 2)

#### Scenario: 低利率最佳投产比

- **WHEN** 某行实际利润率小于等于 50%
- **THEN** 最佳投产比 = ROUND(净保本投产比 × 2, 2)

### Requirement: 采购成本列批量粘贴

采购成本列 SHALL 支持粘贴批量录入：以常见分隔符（逗号、分号、制表符、换行、空格等）拆分粘贴内容，从当前行起依次向后填充；填充完成后 SHALL 自动触发对应行的价格重算。

#### Scenario: 批量粘贴成功

- **WHEN** 用户在第 2 行采购成本框粘贴 `5.94, 6.20, 7.15` 且后续至少有 3 行
- **THEN** 从第 2 行起连续填充三个采购成本值，并分别重算各衍生价格与指标

#### Scenario: 批量粘贴超出剩余行数

- **WHEN** 粘贴拆分后的条目数超过从当前行到末行的剩余行数
- **THEN** 系统填充至末行后终止，并提示已丢弃的超出条目数量

### Requirement: 实时重算

当采购成本、运费、任一「率」类参数或活动配置发生变化时，系统 SHALL 自动重新计算该行的实际拼单价、拼单价、单买价及全部只读指标列。

#### Scenario: 修改采购成本触发重算

- **WHEN** 用户修改某行采购成本值
- **THEN** 该行全部计算列在可计算条件下立即更新

### Requirement: Markdown 导出

系统 SHALL 支持将当前计算器数据导出为 Markdown 格式，并同时：

1. 复制完整 Markdown 文本到剪贴板
2. 下载 `.md` 文件，文件名为 `{goods_id}-{商品标题}.md`（非法文件名字符替换为 `-`）

导出内容 SHALL 包含：

- 一级标题：`# {goods_id}-{商品标题}`（goods_id 取自 URL 参数或页面 tracking；商品标题取自 `#basic.goods_name input`）
- HTML 注释版本标识：`<!-- price-calculator-export v1 -->`
- `## 活动配置` 小节：Markdown 表格，含立减优惠券（元）、限时限量购类型、限时限量购值
- `## SKU 定价` 小节：单表 Markdown，含款式、全部可编辑列及全部计算列

#### Scenario: 导出成功

- **WHEN** 用户点击【导出】且至少有一行 SKU 数据
- **THEN** 系统复制 Markdown 到剪贴板、触发文件下载，并提示成功

#### Scenario: 导出文件名

- **WHEN** 页面 goods_id 为 `984789780623`、商品标题为「测试商品」
- **THEN** 下载文件名为 `984789780623-测试商品.md`

### Requirement: Markdown 导入

系统 SHALL 支持通过【导入】恢复计算器数据。用户 MUST 可选择本地 `.md` 文件或粘贴 Markdown 文本。

导入 SHALL：

- 解析 `## 活动配置` 表格并恢复全局活动配置
- 解析 `## SKU 定价` 表格，按**款式**列（trim 后全等）与当前行匹配
- 仅写入可编辑字段：采购成本、运费、退货率、平台扣点、目标利润率；计算列忽略并由重算覆盖
- 导入完成后自动重算并提示成功/未匹配行数

#### Scenario: 按款式匹配导入

- **WHEN** 用户导入含款式「经典款 / 大号」、采购成本 6.20 的 Markdown，且当前表格存在该款式行
- **THEN** 对应行采购成本更新为 6.20 并重算

#### Scenario: 未匹配款式跳过

- **WHEN** 导入 Markdown 中含当前表格不存在的款式
- **THEN** 系统跳过该行并在完成提示中报告未匹配数量

#### Scenario: 粘贴 Markdown 导入

- **WHEN** 用户在导入弹窗粘贴有效 Markdown 全文并确认
- **THEN** 系统按与文件导入相同规则解析并应用

### Requirement: 脚本匹配范围

脚本 SHALL 仅在拼多多商家后台 `https://mms.pinduoduo.com/` 注入运行（`@match *://mms.pinduoduo.com/*`）。

#### Scenario: 非拼多多商家后台不注入

- **WHEN** 用户访问非 `mms.pinduoduo.com` 域名页面
- **THEN** 脚本不加载，页面无「价格计算」悬浮按钮

### Requirement: 回填原页面表格

活动配置区下方 SHALL 提供唯一「回填」按钮。点击后，系统 SHALL 将所有已计算出有效拼单价与单买价的 SKU 行写入原页面，行列 MUST 与款式行一一对应。不支持逐行单独回填。

优先通过 React `sku.tableList` 批量写入 `multi_price`（拼单价，分）与 `price`（单买价，分），并按款式 `spec` 匹配；匹配失败时按行序兜底。写入完成后 SHALL 自动点击页脚「保存草稿」提交。若无法访问 `tableList`，SHALL 回退为逐行对输入框派发 `input` 事件。

回填进行中 MUST 展示进度或阶段提示，并 MUST 禁用「回填」按钮直至本次回填结束。回填结束后 MUST 提示成功、跳过、失败数量；同一行 MUST NOT 同时计入成功与失败。

#### Scenario: 全部回填成功

- **WHEN** 用户点击「回填」且至少一行拼单价、单买价已有效
- **THEN** 原页面 SKU 价格被更新为各自计算结果，并提示成功数量

#### Scenario: 部分行无效时跳过

- **WHEN** 用户点击「回填」但部分行成本为空导致无有效价格
- **THEN** 系统跳过无效行，回填有效行，并提示成功与跳过数量

#### Scenario: 分批回填与进度提示

- **WHEN** 用户点击「回填」且有效行数量较多，且走事件兜底路径
- **THEN** 系统分批写入并展示进度提示，完成后展示汇总结果；回填期间「回填」按钮不可再次触发

#### Scenario: 结果统计互斥

- **WHEN** 某一行成功写入拼单价与单买价
- **THEN** 该行计入成功，不得同时计入失败

#### Scenario: tableList 回填并保存草稿

- **WHEN** 用户点击「回填」且页面存在 `sku.tableList`
- **THEN** 系统批量更新 tableList 后自动点击「保存草稿」

### Requirement: 脚本目录与说明文档

仓库 SHALL 在 `tampermonkey/price_calculator/` 下提供用户脚本文件与 README。README MUST 包含：环境依赖说明、脚本参数说明、使用配置说明、FAQ 说明。

#### Scenario: 目录结构完整

- **WHEN** 本变更实现完成
- **THEN** 存在 `tampermonkey/price_calculator/` 目录，内含 `.user.js` 脚本与符合仓库规范的 README
